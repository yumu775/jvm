# 架构与一致性

## 模块

| 模块 | 职责 |
| --- | --- |
| `cmd` | 参数校验、命令编排、退出状态和用户输出 |
| `internal/config` | 根目录、默认值、配置规范化、短锁和原子写入 |
| `internal/version` | 版本 ID 校验、真实路径登记、旧目录兼容、数字前缀解析 |
| `internal/env` | 纯激活脚本、用户持久环境、profile 标记块、环境存储接口 |
| `internal/sources` / `alias` | 官方元数据、源启停、版本解析 |
| `internal/download` / `install` | 完整性校验、安全解压、结构规范化与验证 |
| `internal/scanner` / `uninstall` | 有界扫描、外部登记、按所有权卸载 |
| `internal/project` | 查找与读写项目 Java 版本声明 |

## 目录与来源故障

`sources.Catalog` 接受来源、主版本、摘要/完整历史、刷新和离线选项。每个发行版独立查询，最多四个并发来源，每源整个请求周期有时间上限。元数据目录按平台、来源和查询范围缓存 6 小时；故障时可返回 30 天以内的陈旧缓存并标记 `stale`。某个来源失败不抹掉其他来源的结果。

来源与元数据服务不是同一概念：`adoptium` 表示 Temurin，可以使用 Adoptium 官方 API 或同厂商 Foojay 元数据。`zulu` 使用独立 Azul 官方服务；`corretto`、`graalvm` 经 Foojay 查询并补取官方校验信息。默认安装来源独立保存；目录排序优先级不能触发换厂商安装。

列表不为每条历史包请求详情。最终安装前补齐 SHA-256，验证文件身份、平台和校验来源；下载时校验实际字节。元数据备用接口不等同于安装包镜像，健康检查也不保证文件服务器一直可用。

## 四种独立状态

1. 保存的管理版本选择：`config.json` 的 `current_version`。
2. 操作系统/登录 shell 的持久环境：Windows 用户环境或 Unix profile。
3. 当前终端环境：由父进程继承，必须在该 shell 中执行激活脚本。
4. IDE/Gradle 的独立 JDK 配置与现有进程。

这些状态不能假设相同。CLI 必须分别展示，并在无法完成操作时返回非零。跨配置文件与操作系统环境没有全局原子事务；若环境保存成功、版本记录失败，错误会明确指出部分完成的状态。

Windows 通过按用户 SID 命名的内核互斥锁串行执行环境变更命令，锁覆盖整个命令及其配置保存。不同 `JVM_HOME` 仍共享该用户锁；等待超过 15 秒明确报错，错误路径释放锁。临时脚本、只读命令和预览不加锁。互斥避免本工具进程间交错写入，但不等于崩溃原子性，也无法约束外部软件直接改注册表。Unix 尚未提供同级的跨命令环境互斥。

## 安装事务

解析真实发行版 → 检查登记位置与所有权 → 获取目标安装锁 → 下载并校验 → 同盘暂存解压 → 验证 JDK 和 release 主版本 → 旧安装重命名为备份 → 新目录就位 → 登记 → 删除备份。

登记失败会把新目录移回暂存并恢复旧目录。进程崩溃、断电不属于自动回滚保证；遗留锁和备份用于人工恢复。校验不执行刚下载的二进制，不能替代实际 JDK 运行与 IDE 兼容性测试。

归档路径必须位于解压根内；拒绝绝对路径、路径穿越、向已有符号链接写入和指向目录外的符号链接。下载使用临时文件，通过 SHA-256 及可靠的精确尺寸校验后才进入缓存；Azul 的约整大小仅作参考，不能作为精确字节数。

规范化 JDK 目录层级后会再次逐段解析全部符号链接及 `..`，包括悬空链接，拒绝因目录上移而逃出新安装根的目标；合法内部链接保留。

## 目录与所有权

安装、导入、查询、切换和卸载共享安装记录。外部导入不取得文件删除权。托管删除校验保护目录与重定向边界；版本 ID 不允许目录分隔符或路径跳转。

解除外部登记后，`ignored_legacy_paths` 保留目录排除信息，防止旧仓库扫描把仍存在的外部文件重新认领为托管安装。再次显式导入会移除对应排除项。删除父目录时也保护这些保留的外部目录。

配置写入采用同目录临时文件、同步和替换。`config.Update` 对读取—修改—写入使用跨进程短锁，调用者不能在回调中递归请求同一锁。安装与卸载共享目标互斥锁；并发安装不同版本可以下载到同一缓存，最终仍以校验后的完整文件为准。

## 测试边界

默认测试不能写真实注册表、用户 profile 或 JDK。Windows 持久操作经 `EnvironmentStore` 注入内存存储，网络经本地 HTTP 测试服务器，文件操作限定在测试临时目录。

CI 覆盖 Windows、macOS、Linux 的 Go 1.21 和当前稳定版本，并在 Linux 执行 race 检查。CI 配置已提供，但本地 Windows 验证不等于另外两个系统已运行通过。
